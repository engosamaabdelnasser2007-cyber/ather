# أثر — حزمة مراجعة الخطوات 1 إلى 4

- `athar-preflight-readonly.sql`: جرد قراءة فقط للجداول والأعمدة والسياسات والفهارس والقيود والمشغلات.
- `prayer-schema-compatibility-check.sql`: فحص توافق أعمدة الصلاة مع واجهة التطبيق، ويُظهر الجداول والأعمدة المفقودة من دون تعديل قاعدة البيانات.
- `AUDIT-REPORT-AR.md`: نتائج المراجعة وحدود الاختبارات.
- `prayer-times-sync.ts` و`supabase/functions/prayer-times-sync/index.ts`: مسودتا مزامنة محمية بالمصادقة؛ تحتاجان مطابقة المخطط واختبارًا على مشروع تجريبي قبل النشر.
- `supabase/migrations/202610090002_prayer_tables_and_guard.sql`: مسودة migration فقط، غير مطبقة. لا تشغّلها على قاعدة الإنتاج قبل فحص المخطط والسياسات الحالية؛ قد توجد سياسات permissive أخرى أو اختلافات في بنية `profiles`.

## الترتيب الآمن
1. شغّل ملفات الفحص للقراءة فقط أولًا.
2. تأكد من وجود الأعمدة المطلوبة وعدم وجود سجلات مكررة قبل إضافة قيد فريد.
3. راجع كل سياسات RLS الموجودة، لأن السياسات permissive تتجمع بمنطق OR ولا يكفي إنشاء سياسة أضيق مع إبقاء سياسة واسعة.
4. اختبر التغييرات على مشروع تجريبي وحسابين منفصلين.
5. لا تضع مفتاح `service_role` في الواجهة أو في مستودع GitHub.

## حدود التحقق
هذه تغييرات على فرع مراجعة وطلب دمج Draft؛ لم تُدمج في `main` ولم تُطبّق على Supabase ولم يُعلن اجتياز اختبارات تشغيلية.
